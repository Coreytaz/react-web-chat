# React Chat

Фронтенд чата: React 19, TypeScript, Vite 8, Redux Toolkit, TanStack Query 5, React Router 7, Axios и Socket.IO 4. Внешний вид, маршруты и HTTP/Socket.IO-протокол существующего сервера сохранены.

## Запуск

Требуется Node.js 24 LTS и npm. Версия указана в .nvmrc и engines.

```powershell
npm ci
Copy-Item .env.example .env.local
npm start
```

Откройте адрес из вывода Vite (обычно http://localhost:5173). npm run dev — синоним npm start.

| Переменная      | Локальная разработка   | Production                                                            |
| --------------- | ---------------------- | --------------------------------------------------------------------- |
| VITE_API_URL    | /api/                  | Полный HTTPS URL API с /api/ либо /api/ при собственном reverse proxy |
| VITE_SOCKET_URL | Пустая: текущий origin | Полный HTTPS URL Socket.IO либо текущий origin при reverse proxy      |
| DEV_BACKEND_URL | http://localhost:5000  | Не используется                                                       |

При миграции переименуйте REACT_APP_API_URL → VITE_API_URL и REACT_APP_SOCKET_URL → VITE_SOCKET_URL. VITE_* попадают в браузерный bundle: секреты туда помещать нельзя. После изменения окружения перезапустите Vite; для production пересоберите приложение.

Dev proxy проксирует /api и /socket.io на DEV_BACKEND_URL. Только в dev-ответах он убирает Secure из cookie и переписывает домен: это позволяет локально использовать текущий сервер с secure cookies и фиксированным CORS. Сам сервер менять не требуется. Production использует серверные cookie без преобразований и требует HTTPS и корректного CORS/SameSite на стороне сервера.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
npm run preview
```

build выполняет проверку TypeScript и создаёт dist. preview показывает production bundle, но не предоставляет dev proxy. Для проверки preview с API укажите подходящие VITE_* при сборке или используйте собственный reverse proxy. Vercel настроен на dist и SPA fallback; в настройках проекта задайте адреса существующего API и Socket.IO. Автоматическая публикация в рамках рефакторинга не выполняется.

test:integration запускает отдельный сервер fixture на свободном локальном порту и проверяет две независимые HTTP-сессии, доставку Socket.IO, историю, редактирование, удаление и reconnect. Это проверка протокола с fixture, не настоящего бэкенда.

Тесты: Vitest + Testing Library + MSW 3 (HTTP), управляемые Socket.IO и media API. Проверяются авторизация и выход, сетевые ошибки, возврат на защищённую страницу, поиск с debounce, смена диалога, пагинация, гонки истории/событий, редактирование, вложения и освобождение микрофона.

## Локальная проверка без настоящего бэкенда

В первом терминале:

```powershell
node tests/fixtures/server.mjs
```

Во втором терминале:

```powershell
$env:DEV_BACKEND_URL='http://127.0.0.1:5050'
npm start
```

Сервер fixture слушает только 127.0.0.1:5050 и хранит вымышленные данные в памяти. Логины alice и boris, любой непустой пароль. Для двух независимых сессий используйте разные браузерные профили. Поддержаны вход/выход/refresh, профиль, друзья, поиск, история и отправка/редактирование/удаление сообщений. Регистрация, загрузки, реальные приглашения и серверная очистка этим fixture не реализованы; media и uploads проверяются автоматическими тестами. Fixture не предназначен для публикации.

## Организация данных

Redux хранит авторизацию, онлайн-статусы и уведомления. TanStack Query — друзей, заявки, поиск, пользователей и страницы истории. Ключи кеша включают аккаунт и параметры запроса; запросы отменяются через AbortSignal. Socket.IO подключён на уровне сессии и повторно регистрирует пользователя при reconnect. События сообщений хранятся в кеше с ревизиями: события, пришедшие во время запроса истории, не теряются, а старые события не восстанавливают удалённые сообщения после refetch. На выходе или API 401 приватный кеш очищается.

Временные состояния загрузки вложений, формы и редактирование остаются локальными. Отмена записи и уход из диалога останавливают media tracks и отменяют загрузку аудио.

## Версии и ограничения

Версии прямых зависимостей зафиксированы вместе с package-lock.json. Используются последние стабильные версии на момент обновления. Исключение: TypeScript 6.0.3 вместо 7, поскольку установленный typescript-eslint поддерживает TypeScript <6.1. Не применялись --force или --legacy-peer-deps.

Локальный backend находится в соседнем проекте `D:/project/React_Chat_Back`. Он проверяет cookie JWT для HTTP и Socket.IO, ограничивает события участниками переписки и сообщает об ошибках через `operation:error`. Очистка переписки удаляет только собственные сообщения. Исторические названия HTTP-маршрутов и Socket.IO-событий сохранены.

История использует page/limit: при одновременных изменениях возможны сдвиги страниц. Фронтенд устраняет дубли по ID и согласует историю с событиями. Полная гарантия непрерывности истории потребовала бы cursor pagination на сервере.

## Как устроен код

- `pages/` — композиция экранов и параметры маршрута. Страницы загружаются через `React.lazy`; компоненты переписки — после авторизации, панель эмодзи — при открытии.
- `components/` — разметка и взаимодействие с интерфейсом. Импорты компонентов прямые, без общего barrel-файла и циклических зависимостей.
- `components/Form/AuthForm.tsx` — общая форма входа и регистрации с описанием полей; сетевой сценарий находится в `hooks/auth/useAuthenticate.ts`.
- `hooks/chat/` — черновик сообщения, загрузки/отмена вложений, воспроизведение аудио, история и сохранение положения прокрутки. `useChat` отвечает за подписки и жизненный цикл socket-соединения.
- `service/chat/message-events.ts` обновляет кеш по socket-событиям; `message-cache.ts` объединяет его с HTTP-историей. Объединение пересчитывается только при изменении страниц или событий.
- `components/UserBlock/` — общие списки пользователей, поле поиска и входящие заявки. Действия дружбы находятся в `hooks/user/useFriendActions.ts`; обновление списков выполняется по событиям сервера, без задержек через таймеры.
- `hooks/user/useAccountMutation.ts` — общая обработка ошибок профильных запросов и защита от применения запоздавшего ответа после смены аккаунта.
- `types/` — модели `PublicUser`, `SessionUser`, `AuthResponse`, `ChatMessage` и `Attachment`. Серверные данные хранятся в TanStack Query, текущая сессия/online/уведомления — в Redux, черновики и раскрытые меню — в локальном состоянии.

При добавлении поведения оставляйте разметку в компоненте, а самостоятельные сетевые или браузерные сценарии — в профильном хуке. Маленькие UI-компоненты не требуют отдельного хука. `memo` используется для сообщений и аватаров; селектор online-статуса подписан на конкретного пользователя, чтобы изменения чужого статуса не обновляли все строки.
